Noted it in the backlog: `docs/backlog/top-form-nested-comment-sent-whole.md`, committed on its own as `Backlog: Evaluate Top Form sends a nested comment block whole` (`375a1b5`).

One correction from checking the code: the behavior belongs to **Evaluate Top Form**, not Evaluate Current Form. `topFormAtCursor` (`src/repl/forms.ts:320`) descends into a bare `(comment …)` exactly once and returns the body form as-is, so a nested comment comes back whole. That was a deliberate design line in `docs/plans/2026-09-05-2253-evaluate-top-form.md` and is pinned by a test (`src/test/forms.test.ts:424`, `(comment (comment |x))` → `(comment x)`). Evaluate Current Form uses `formAtCursor`, which resolves the innermost form and does not know about `comment` at all; I verified `(comment (comment (+ 1 |2)))` gives `2` from it, so it is unaffected.

The entry records the repro, the cause, that the one-level rule was a decision rather than an oversight, and a proposed fix: loop the existing `commentHeadEnd` / `resolveCommentBody` pair until the resolved form is no longer a comment list (about eight lines, plus flipping the pinned test, adding a cursor-on-inner-head case, and updating the docstring and README wording). Nothing else was changed.
